# Requirements: Blog X v1.4 Post-launch Hardening

## Security and Recovery

- [x] **SEC-04**: 管理员可在已认证后台验证当前密码并设置新密码；成功后撤销其他会话、记录审计事件，密码和哈希不出现在日志、响应或仓库中。
- [x] **SEC-05**: 正式入口提供合理的 HSTS、内容类型、Referrer、frame、Permissions Policy 和完整 CSP，并隐藏不必要的框架标识，不破坏现有页面、媒体和管理功能。
- [x] **CONT-09**: 管理员可查看软删除文章并明确恢复为非公开草稿；恢复不泄漏内容、不绕过 Slug 保留和审计边界。

## Media and Backup

- [x] **MEDIA-02**: 管理员可分页浏览、搜索和复用已上传媒体，看到引用状态，并仅在未被内容引用时安全删除媒体。
- [x] **OPS-06**: 每日数据库、媒体与关键配置备份可通过可配置传输同步到异地主机或对象存储，失败可观测，保留策略有界，并有不接触生产的恢复验证。

## Continuity and Operations

- [x] **SITE-01**: 管理员可维护站点名称、简介和公开展示信息，备案号仍保留安全默认值且不会因普通内容编辑意外移除。
- [x] **LINK-01**: 已发布文章修改 Slug 后，旧地址以持久重定向到当前地址且不会形成重定向环。
- [x] **CONT-10**: 文章服务端保留有界历史版本，管理员可比较并恢复为草稿，不自动覆盖当前公开版本。
- [x] **OPS-07**: 访问统计与过期会话具备定时清理；健康、备份、调度、证书和资源异常可以通过不含秘密的状态与通知接口发现。

## Constraints

- 保持单管理员、同源入口、PostgreSQL 和两台低配置服务器架构，不引入 Redis、搜索集群或重型常驻服务。
- 开发与自动验证先在本地完成；不得自动修改 `main`，不得把生产凭据写入仓库。
- 真实服务器部署、密码轮换和异地目的地接入必须经过单独生产门禁。
- 每个阶段只运行针对性测试、构建和浏览器烟测；发布准备阶段再执行完整恢复与集成验证。
