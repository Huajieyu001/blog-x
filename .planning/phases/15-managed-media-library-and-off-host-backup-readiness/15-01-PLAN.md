# Phase 15 Plan 01: Media Reference Authority

## Objective

Turn the existing media catalogue into a single fail-closed ownership authority: list/reuse remains lightweight, while deletion is allowed only when the exact asset has no reference anywhere content can retain it.

<objective>
Turn the media catalogue into a fail-closed ownership authority: listing and reuse stay lightweight, while deletion is allowed only when the exact asset has no reference anywhere retained content can reference it.
</objective>

  <behavior>
    - Catalog q is trimmed and bounded; ordering is createdAt DESC/id DESC and pagination has no duplicate/omitted retained row across adjacent pages.
    - Reference counts use parsed real image URLs and cover IDs, de-duplicate repeated uses per owning record, include every article lifecycle state, About Markdown, and conservative settings occurrences; UUID-looking prose, links, and code blocks do not count.
    - Unknown/deleted IDs remain indistinguishable as not_found; a referenced ID returns a minimal 409 count; parsing/database/lock/storage anomalies return a stable no-path failure and preserve row/files.
  </behavior>
  <action>Write failing API/service tests first. Extend the shared reference policy rather than regex-scanning arbitrary Markdown. In the delete transaction, acquire a deterministic transaction-scoped advisory lock for the media ID, read only required article/About/settings projections, calculate opaque owning-record counts, and only then mark the row deleted plus append the existing content-free audit event. Reuse the same sorted lock/retained-media validation in article, About, and site-settings write authorities before they can commit a new reference, preventing a delete/write race. Keep storage cleanup after the committed tombstone, preserve retryable cleanup-pending behavior, and never return keys, paths, titles, Markdown, or settings text. Keep route authentication, exact Origin/content-type, body bounds, and mutation inventory unchanged; add only strict parsers/responses needed for stable 400/404/409/503 outcomes.</action>
  <acceptance_criteria>
    - A media used only by a deleted article, a draft, a cover, About, or site settings is not deletable.
    - A truly unused media row is tombstoned and both exact objects are removed; failure leaves no public storage detail and no false success.
    - Parallel delete/reference-add attempts serialize to either a retained usable asset or a rejected content mutation—never a saved dangling `/media/` reference.
    - No Drizzle schema, migration, `drizzle push`, broad SQL interpolation, dependency, or permanent broad cleanup is introduced.
  </acceptance_criteria>
