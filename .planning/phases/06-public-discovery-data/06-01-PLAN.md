<interfaces>
- Constants are exact: `publicSearchPageSize = 10`, `publicSearchMaxPage = 100`, `publicSearchMaxQueryCodePoints = 80`, `publicSearchMaxRawCodeUnits = 256`, `publicRelatedPostLimit = 4`.
- `publicSearchQuerySchema` accepts exact keys `q` and `page`; missing q becomes empty, page defaults to 1, repeated Fastify array values and unknown keys are invalid, and normalization order is raw-length check -> NFC -> Unicode trim -> code-point count.
- Search response is a strict coherent union over `empty_query | no_results | results | page_out_of_range` with exact common fields `{ state, query, page, pageSize, totalItems, totalPages, items }` and existing `PublicPostListItem` values only.
- Known discovery failures have separate strict schemas: invalid query, invalid page, search timeout, and a route-local unexpected-error body exactly `{ error: "discovery_error" }`. The last schema is shared by search and related HTTP 500 responses so neither route depends on Fastify's default error serializer.
- Empty query has empty normalized query, zero counts/items, and no repository scan. No-results has a non-empty query and zero counts/items. Results has positive totals and non-empty page items. Out-of-range has positive totals, requested page above totalPages, and empty items.
- Search match SQL binds one escaped pattern and uses `normalize(field, NFC) ILIKE pattern ESCAPE '\\'` for title, summary, and Markdown. Fixed SQL is allowed in Drizzle `sql` templates; visitor bytes are never interpolated as SQL tokens.
- Ranking is one CASE class, not additive: title 3, else summary 2, else Markdown 1; order is class DESC, published_at DESC, id DESC.
- Search count and rows run in one `repeatable read`, `read only` transaction after `SET LOCAL statement_timeout = '2000ms'`; only PostgreSQL cancellation code `57014` is wrapped as `SearchUnavailableError`.
- Extract one repository-local `hydratePublicCards(tx, rows)` that batches category/tag hydration only for selected rows and preserves tag order by name then ID. `listPage` may reuse it, but its existing wire behavior and ordering must remain unchanged.
- No database schema or migration file changes in this plan.
</interfaces>
