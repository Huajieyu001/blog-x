# Quick 260831-hh1: Administrator audit trail

## Outcome

Provide an authenticated, responsive administrator audit page backed by a bounded append/list API. Record successful login/logout, article lifecycle, taxonomy, and About changes with the authenticated administrator UUID and allowlisted metadata only.

## Tasks

1. Add strict contracts, PostgreSQL schema/migration, append-only repository, and cursor-paginated admin API.
2. Make successful session, article, taxonomy, and About mutations append exactly one event in the same database transaction.
3. Add `/admin/audit`, navigation, responsive presentation, and focused API/browser tests.
4. Run repository gates, refresh the fixed local preview on port 3100, independently review, deliver once for the final implementation SHA, commit the receipt, and push `dev`.

## Security and scope

- Store IDs, event enums, outcome, timestamps, bounded changed-field/status metadata only.
- Never store passwords, tokens/digests, cookies, request/response bodies, Markdown, filenames/paths, raw IPs, headers, or environment data.
- Expose append/list only; no application update/delete endpoint.
- Use keyset pagination with default 25 and maximum 50; responses are administrator-only and `no-store`.
- Database-owner/runtime-role separation and external integrity checkpoints are production hardening work; this phase does not claim protection from a database owner.
- Do not connect to either cloud server.
