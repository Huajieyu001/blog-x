# Blog X 发布门禁

> 当前状态：BLOCKED  
> 本地状态：安全、备份与恢复策略已验证  
> 生产状态：所有主机、网络、证书和外部服务证据待未来单独授权

本文是 STOP/GO 证据流程，不是部署指南。它不能解除冻结、连接节点或执行发布。成功的本地测试、Git 提交、时间经过以及生成夹具都不是生产授权。

## 角色和判定原则

| 角色 | 职责 |
| --- | --- |
| 用户/变更批准人 | 以新的明确消息解除冻结，给出命名范围和有限变更窗口 |
| 发布责任人 | 汇总证据引用与哈希，逐项作出 STOP/GO 判定 |
| 基线核验人 | 在另行批准后采集两个节点的只读基线，不执行修改 |
| 恢复核验人 | 独立确认完整备份、隔离恢复和已知良好备份仍可用 |
| 发布后核验人 | 执行公开入口冒烟检查并记录继续或回滚决定 |

任一字段缺失、过期、失败、含秘密或无法独立复核，结论必须为 STOP/BLOCKED。任何角色都不能用本地或合成证据替代生产事实。

## 单向证据顺序

1. **明确解除冻结**：必须有未来用户消息，写明允许操作的节点角色、发布范围、窗口开始/结束和批准引用。缺失时不得进入生产只读检查。
2. **授权的只读基线**：分别记录主入口节点与内部节点的受支持系统状态、服务/端口/防火墙、CPU/内存/磁盘、现有边缘配置以及维护页保留状态。历史基础设施文档不能充当当前基线。
3. **网络边界**：证明浏览器仅使用博客 HTTPS 同源页面、API 和媒体路径；API 与 PostgreSQL 不公开；节点间私有链路或经过认证的加密链路已经核验。
4. **完整备份与隔离恢复**：引用最近 24 小时内的完整集合、每日调度结果、异机目的地、保留决策、加密密钥权威、已知良好备份和最近隔离恢复报告。
5. **运行与证书**：引用实际节点的进程恢复、日志上限、资源限制、健康状态、证书有效性与续期检查，并记录告警接收决策。
6. **回滚就绪**：引用不可变的上一版 Web/API 摘要、上一版边缘配置校验和、迁移兼容性、数据库/媒体保全、责任人、触发条件、停止条件与独立验证结果。
上述六项只能产生临时的 `PRE_RELEASE_READY` 判定；它不写回仓库、不能执行动作，也不要求发布后的事实。随后是否执行发布是仓库外、另行授权的人为决定。只有该外部动作已经发生后，才可收集下一项证据：

7. **发布后验证**：在实际 HTTPS 域名完成首页、公开文章、媒体、管理登录和健康冒烟检查，并将部署产物摘要、冒烟结果和继续/回滚决定与前一份判定的实际字节和决策 ID 绑定。全部通过才产生临时的 `POST_RELEASE_VERIFIED`；失败的冒烟或回滚决定是明确的非成功结论，不会伪装成格式错误。

门禁工具只读取本地证据包、校验类型/时间/哈希，并可输出 `PRE_RELEASE_READY`、`POST_RELEASE_VERIFIED`、`POST_RELEASE_FAILED`、`BLOCKED` 或 `INVALID`；它不提供网络、状态迁移或部署能力。

## 不可推断的决策槽

以下值必须由未来授权流程提供引用，仓库不保存其真实值：

- 变更责任人和有限变更窗口；
- 节点资源限制与支持状态；
- 防火墙及私有/加密链路实现；
- 异机备份目的地、保留决策、加密密钥权威和告警接收人；
- 证书当前状态与续期结果；
- 经选择并测量的 RPO 与 RTO；
- 发布后冒烟结果和继续/回滚决定。

## 当前结论

仓库中的 `ops/release-evidence.blocked.json` 只列未解决原因，不包含生产证据定位符。当前结论始终为 **BLOCKED**。只有未来明确解除冻结并完成全部新鲜发布前证据后，临时证据包才有资格接受 `PRE_RELEASE_READY` 评估；任何生成结果不得回写为仓库真实状态。

## 本地验收收据的边界

完整 Phase 1–5 本地门禁必须先运行在干净、已提交的实现版本上。仅当所有本地套件、生成的 collector-to-mounted 流程、假故障覆盖、清理/并行检查和最终 canonical `BLOCKED` 判定都成功后，才可以原子写入 `ops/phase5-full-gate-receipt.json`。收据只绑定实现提交、命令、红摘要和本地生成范围；它不是异机挂载、调度、告警投递、TLS、部署或发布后行动的证明。

收据验证完成后，里程碑审计才可以在后续的单独证据文档提交中引用其精确 SHA-256 和实现版本。实现提交不得包含收据或通过的审计。
