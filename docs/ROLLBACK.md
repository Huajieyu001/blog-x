# Blog X 回滚决策手册

> 当前状态：BLOCKED；没有生产授权，也没有可执行的远程或自动回滚入口。

回滚的目标是恢复已独立验证的上一版服务，同时保留当前数据库、媒体、配置、日志和备份证据。它不是删除当前状态后“重新试一次”。

回滚决定属于外部发布动作之后的 `POST_RELEASE_VERIFIED` 证据：它必须绑定实际的前一份 `PRE_RELEASE_READY` 决策和部署产物摘要。仓库中的校验器只验证记录，绝不会开始、继续或执行回滚。

## 前置条件

- 发布责任人和回滚责任人已经命名，变更窗口仍有效。
- 上一版 Web 与 API 是按内容摘要锁定的不可变产物，不使用可移动标签。
- 上一版边缘配置有独立校验和与语法验证结果。
- 已记录数据库迁移向前/向后兼容决定；无法安全降级时只允许回退应用并保持兼容数据库版本。
- 当前数据库与所有 source/derivative 媒体已保全，禁止先删除、覆盖或重建。
- 完整且已知良好备份仍在独立位置，并有成功隔离恢复证据。
- 已定义触发条件、停止条件、冒烟检查和最终决定记录位置。

缺少任一前置条件即 STOP，不启动回滚。

## 决策点

1. **触发判断**：公开入口、文章、媒体、管理登录、数据完整性或资源健康出现已定义失败时，由责任人记录证据。
2. **保全判断**：确认当前数据库、媒体、配置和日志已经保留；若保全失败，停止所有替换动作。
3. **兼容判断**：根据迁移兼容记录选择仅回退 Web、仅回退 API、共同回退应用，或停止并进入数据恢复评审。不得猜测数据库降级安全性。
4. **边缘判断**：只有上一版边缘配置校验和与独立验证一致，才可纳入回滚变更。
5. **继续判断**：每个角色级动作后执行预先列出的健康与数据检查；任一失败立即按停止条件退出。
6. **完成判断**：独立验证首页、公开文章、媒体、管理登录、API 健康和内容完整性后，由责任人记录“保持回滚版本”或“继续处置”。

## 必需证据字段

| 类别 | 必需内容 |
| --- | --- |
| 不可变应用产物 | 上一版 Web 摘要、上一版 API 摘要 |
| 边缘配置 | 上一版配置校验和、语法/行为验证结果 |
| 数据库 | 当前备份引用、迁移兼容决定、禁止破坏性重置 |
| 媒体 | source 与 derivative 保留方案及字节验证结果 |
| 所有者 | 发布责任人、回滚责任人、独立验证人 |
| 判断 | 触发条件、停止条件、冒烟清单、最终决定与时间 |

## 停止条件

- 摘要、配置校验和或已知良好备份不匹配；
- 数据库迁移兼容性未决定或数据/媒体保全未完成；
- 责任人、窗口或授权已经失效；
- 独立验证发现内容缺失、媒体字节不一致、非公开内容泄漏或健康检查失败；
- 操作目标不再是已核验的精确角色/产物，或需要扩大授权范围。

## 独立验证与记录

回滚完成不能以“动作没有报错”为依据。验证人必须对公开入口、发布文章、媒体、后台登录、API 健康、数据库权威和备份保留逐项签署结果。记录只引用非秘密的证据 ID、时间、摘要和结论；不得记录凭据、节点地址或内部连接信息。
